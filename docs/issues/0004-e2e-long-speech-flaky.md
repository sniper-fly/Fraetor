# 0004: E2E `test_long_speech_all_sentences_survive_incremental_flush` が不安定

## 現状

`tests/e2e/test_mic_and_vad.py::TestFileAudioAndVad::test_long_speech_all_sentences_survive_incremental_flush`
(`06_long_speech.wav` を `segment_silence_sec=0.45` で逐次flushし、5つのキーワードが全て認識結果に
含まれることを検証する)が、同じコードで通ったり落ちたりする。

2026-10-25 に、同一テストを同一環境で繰り返し実行して確認した。

| 対象 | 通った | 落ちた |
|---|---|---|
| dictationをライブラリ化する前のコミット (`0c5467a`) | 5回 | 4回 |
| ライブラリ化後 | 4回 | 1回 |

ライブラリ化前のコミットでも落ちるため、ライブラリ化(`fraetor-dictation` への切り出し)が
原因ではない。

## 課題

- **落ちたときに、5つのキーワードのうちどれが欠落したかは未確認。** 実行出力を `-q` で絞っていたため
  assertion メッセージ(`'<keyword>' を含む文が失われた: <認識結果全文>`)を取得できていない
- 原因は未特定。テスト自身の docstring は「文の途中で flush が発火して極端に短い音声クリップが
  送られると、Azure 側の認識精度が落ちてテキストが欠落しうる」としているが、これが今回の失敗の
  原因であるかは確認していない
- 失敗した実行のログ末尾には `MAI Transcribe stopped (chars=0)`(最終の送信で認識結果が空)と
  `Session transcribed: ... (timed_out=True, segments=4)` が出ていた。このテストの音声は末尾に
  10秒以上の無音がある(テストのdocstringより)ため、最終送信が空になるのは正常な可能性もあるが、
  合格時のログと比較していないので、欠落との因果は未確認。ログ全体も確認していない
- 不安定なテストが残ると、本当の回帰(「1回のflushに複数発話が含まれると最後の発話より前が消える」既知バグ
  の再発)と区別できなくなる

## 検討したい対応案

1. まず原因を特定する。落ちた実行の全出力(`-q` なし、`-s` 付き)を残し、欠落したキーワードと、その時の
   flush 回数・各 flush に送られた音声の長さを突き合わせる
2. 原因が「実クラウドの認識揺れ」なら、5つ全てを必須とせず、欠落許容の閾値を設けるか、
   複数回実行して過半数で判定する
3. 原因が dictation 側の flush 制御にあるなら、ライブラリ側 (`fraetor-dictation`) で再現テストを書いて修正する
   (境界ドキュメント `docs/boundary.md` に従い、ライブラリの責務はライブラリで直す)

## 背景

2026-10-25 のセッションで、dictation のライブラリ化後に E2E を再実行した際、このテスト1件のみが
失敗した。当初「実クラウド依存の揺れなので無関係」と決めつけそうになったが、変更前のコミットで
同じ条件の再実行を行い、既存の不安定さであることを確認した。
