# 0003: 意図翻訳レイヤーのシステムプロンプトがコードエディタ以外の画面に未対応

## 現状

`src/shared/config/settings.py` の `_DEFAULT_INTENT_TRANSLATION_PROMPT`(意図翻訳レイヤーが
Vision LLM に渡すシステムプロンプト)は、VSCode/Cursor のようなコードエディタ画面を前提に、
「コードエディタのメインペイン→ハイライト・選択中の行→ファイルパスのパンくずリスト」という
対象特定手順(手順1〜3)で構成されている。これは実機検証(Cursor画面+「これどういう意味ですか？」
的な発話)で動作を確認済みだが、検証したのはコードエディタ画面のみ。

## 課題

意図翻訳レイヤーの応用可能性について、以下4パターンを想定していた。

1. デバッグ中の質問(コードエディタ画面前提) — 実機検証済み、現行プロンプトで対応済み
2. ダッシュボード/ログ画面を見ながらの調査依頼(例:「このグラフのスパイクなんで起きてるか調べて」)
3. 仕様書やSlack/Figmaを見ながらの実装橋渡し(例:「ここに書いてある通りにこの関数直して」)
4. ペアプロ・画面共有中の高速指示(複数の画面種別が混在しうる)

現行プロンプトの対象特定手順は「コードエディタのメインペイン」「ハイライト・選択状態」
「ファイルパスのパンくずリスト」の存在を前提にしており、これらが存在しない画面種別
(グラフ・ログビューア、チャットUI、Figma等のデザインツール)では、対象特定の手がかりが
機能しない可能性が高い(未検証)。2・3・4のパターンは実装(`src/intent_translation/`)自体は
完了しているが、プロンプトの妥当性を実機検証していない。

## 検討したい対応案

1. 画面種別を判定する前段のステップをプロンプトに追加し、種別ごとに参照すべき視覚的手がかり
   (グラフの軸・凡例、チャットの発言者・タイムスタンプ、Figmaのレイヤー名等)を分岐させる
2. 画面種別ごとに別のシステムプロンプトを用意し、事前設定または画面のスクリーンショットから
   種別を判定して切り替える
3. 汎用化を優先せず、まずは各画面種別ごとに実機検証してから、共通化できる部分だけを抽出する

## 背景

2026-08-18のセッションで、意図翻訳レイヤー(機能4)の技術検証・実装を行った際、この機能の
応用可能性についてユーザーと議論し、上記4パターンの応用例を挙げた。実装は完了したが、
システムプロンプト自体はコードエディタ画面での実機検証結果のみを反映しており、他の画面種別
への対応は未検証・未実装のまま残っている。
